# MailCraft roadmap

## Despres Connect edition integration (2026-10-18)

This branch integrates the upstream 0.4.3 development work while retaining Despres Connect automatic setup and domain discovery, CalDAV/CardDAV sync and conflict handling, iCloud service discovery and sign-in improvements, saved-credential invalidation on server changes, and the original teal/ivory icon. Existing accounts retain their endpoints. Migration and regression checks are required before replacing the working app. See [README](README.md) for this edition's public downloads; upstream build availability does not imply these additions.

The gap between the two readiness numbers is the story of this release: the mailbox, the
commands, the interface and the file formats are in good shape, and the connection to real mail
servers is the thinnest part: two-way and with Microsoft sign-in since 2026-10-12, in use on one
Microsoft 365 mailbox, and not yet run against any other server.

## Where it is strong

- The engine: every action a command, undoable, with a failed command leaving nothing behind and
  every command fuzzed with junk parameters.
- The readers: messages, calendars, contacts and server responses are treated as hostile and
  property-tested with arbitrary bytes.
- Privacy by default: nothing in a message runs or is fetched; passwords and sign-ins are kept only
  by the operating system's credential store, never in MailCraft's own files.
- One code base for desktop and browser.
- Agent control: CLI, control channel, MCP.

## What stands between here and beta

Since 2026-10-14 the way to beta is the roadmap reset: beta is for Microsoft accounts, with
the pass/fail checklist and the
steps R1–R8 (tracked in
[#2](https://github.com/UCS-Care-Group/mailcraft/issues/2)): hygiene; Exchange Web Services removed;
Microsoft Graph for mail; rich-text replies; sign-ins remembered on Linux; message bodies read
when needed; system notifications and Copy diagnostics; then a beta run with testers.

## After beta

Not scheduled; in the order of how much each matters to someone leaving Outlook. Each is a
shortfall in [`docs/gaps.md`](docs/gaps.md).

1. New mail the moment it arrives on IMAP accounts (IDLE), not at the next run (gap 2).
2. Undo Send and Delay Delivery, with an Outbox that also holds mail written offline (gap 17).
3. Calendars and contacts beyond Microsoft (CalDAV, CardDAV, subscribed calendars) and Google
   accounts (gaps 3, 5).
4. Microsoft To Do, with My Day and flagged mail; the organisation's directory, and LDAP, when
   addressing (gap 17).
5. Focused Inbox kept in step with Outlook; Automatic Replies; rules kept on the server (gap 17).
6. Snooze, Sweep, Ignore and Clean Up Conversation, Search Folders, Quick Steps (gap 17).
7. Read receipts, one-click unsubscribe, attachments inside `winmail.dat`, Forward as Attachment
   (gap 17).
8. Warnings about a sender (failed authentication, a name that hides another address, outside the
   organisation, a link that goes somewhere other than it says) and Report Phishing (gap 17).
9. Search that goes on to the server for mail not on this computer (rough edges).
10. Shared and delegated calendars with their permissions, free/busy across the organisation, rooms
    (gaps 9, 17).
11. Spell checking while writing (gap 7).

## The browser build

MailCraft also builds for the browser (WebAssembly), from the same code. Every change is checked to
build, and each release carries it as a download, but it has not yet been reviewed in use, and it
can't connect to a mail server (a browser can't open the connections IMAP and SMTP need): it opens
the sample mailbox and mailboxes kept in the browser. Planned, after beta:

1. Review it: run it in the main browsers, and list what works, what doesn't and what is missing.
2. Decide what it is for, from that review: a demonstration of the program, or a mail client of
   its own. Microsoft Graph runs over HTTPS, so a browser can reach a Microsoft account directly,
   which is what would make it the second.
3. Plan the chosen way, with its own steps here.
